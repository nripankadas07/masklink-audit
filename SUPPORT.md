# Support, contributions and security

Open a reproducible GitHub issue with the command, Python/platform version, expected result
and a minimal synthetic fixture. Do not attach credentials or private data. This is an
experimental bounded MVP; support has no response-time guarantee.

For contributions, keep the documented input contract explicit, add a meaningful regression
case, and run `python verify.py`. Do not remove validation to make broken inputs pass.

For a suspected sensitive vulnerability, use the repository Security tab if private reporting
is available; otherwise describe only a non-sensitive summary and request a private channel.
Do not publish exploit details or real source data in an issue. Inputs may contain sensitive
data; run only on authorized files and review reports before sharing them.
